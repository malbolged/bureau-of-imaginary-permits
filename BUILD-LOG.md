# Build log

Running log of decisions, dead ends and pivots, written as they happen. The "My Build Process" section of the DEV post is written from this file.

Tooling: Claude Code (Opus 5.5) in a Windows terminal. I prompt, it builds; I make the calls on scope and taste.

## 2026-10-01

- **Idea.** Asked Claude for three "strange" ideas that could use both bonus areas (App SDK + Workflows). Picked the Bureau of Imaginary Permits: citizens apply for permits for things that don't exist, an AI clerk does intake, a human Under-Secretary stamps.
- **"Workflows" turned out to be a real product, not a pattern.** First instinct was to hand-roll a `workflow` schema type (stages[], transitions[]). Before writing it, Claude followed the link behind "Workflows" in the challenge post and found `@sanity/workflow-engine` (0.36, early access, on npm): workflow definitions are deployed as `sanity.workflow.definition` documents, instances are `sanity.workflow.instance` documents, transitions are gated by GROQ, and side effects are queued for a runtime to drain. Dropped the hand-rolled version; the approval chains run on the real engine.
- **Found the App SDK adapter too.** `@sanity/workflow-sdk` drives an engine session from the App SDK document store (`useWorkflowSession`, `useWorkflowInstances`), and `@sanity/workflow-diagram` renders a definition as a stage diagram. So the stamp desk can be an App SDK app that talks to the engine directly, with the human's own identity recorded as the actor on every stamp.
- **Modelled on Sanity's "AI content pipeline" cookbook.** Its shape (agent effect, then a GROQ-gated transition that only routes to a human when something is flagged) maps 1:1 onto "clerk reviews paperwork, Under-Secretary stamps".
- **New Sanity project** (`e23lrcxv`) instead of reusing the Path One project, so the two entries' datasets don't mix. Two public datasets: `production` (permits, departments, forms, applications) and `workflows` (the engine's definitions + instances).
- **Judges can't log into an App SDK app** (it's behind Sanity org auth). So at least one permit type runs on a workflow with no human stage, and the public site shows the live stage diagram and history, so the loop can be closed without an account.
- **Three approval chains as data.** `standard-permit` (clerk, then one human stamp), `express-permit` (clerk only), `sky-permit` (clerk, then a second agent, the Ministry of Weather, then two human signatures). Each `permitType` document names its chain. Stage builders (`intake()`, `stamping()`) keep the three definitions short.
- **The engine's validator caught a real bug on the first deploy:** `express-permit` had a `denied` stage that nothing could reach. `sanity-workflows deploy --check` refuses unreachable stages. Removed it.
- **Engine documents are private even in a public dataset.** Definitions and instances use dotted IDs (`prod.standard-permit.v1`, `prod.wf-instance.…`), and the Content Lake never serves dotted IDs to anonymous reads. So the public site reads them server-side and shows them, instead of linking straight to the dataset.
- **The runtime is the Next.js server, not Sanity Functions.** `deploy --check` offered to generate a Functions blueprint (a drain function plus a heartbeat), but the heartbeat is daily on the Free plan. Our only effects are the two agents, and they're always queued by a server request we control, so the server drains them right there. A human stamp from the desk needs no runtime at all: `fireAction` runs the cascade itself.
- **Guardrails around the AI clerk, in code, not in the prompt:**
  - Prerequisite permits are checked deterministically. The citizen quotes a permit number, and the code checks that the referenced application has the same name and that its *workflow instance* is in `issued`.
  - The clerk may only request a form that is attached to that permit type. An unknown code falls back to the first allowed form.
  - After 2 requests for more paperwork, the code forces the ruling to "complete" ("passed for stamping out of sheer fatigue"). Without this, a strict model can bounce a citizen forever. Kafka would approve; judges wouldn't.
- **Smoke tests passed for all three chains:**
  - Express: Licence to Whistle on Tuesdays went from filing to issued in about 15 s.
  - Standard: a haunting licence was sent back twice (Form 88-H, then Form 9-Ω, both times correctly, for the missing "how long in residence" and the vague hours). It passed on the third try, was stamped, and was issued. A stamp attempted while the file waited on the citizen was refused by the engine (`Activity "stamp" not found in current stage "awaiting-citizen"`).
  - Sky: the cloud deed was refused for lacking a Licence to Look Up. After the citizen quoted their licence number, the Ministry of Weather ruled ("Phibsborough, sofa-shaped, backing south-easterly…"), then the stamp and the countersignature led to issued.
- **Latency:** filing is about 6 s (one write to the content dataset, then the instance start). A clerk ruling takes 8–30 s on free-tier Gemini. So the web app must answer straight away and let the clerk work in the background.
- **Public site (Next.js 16)** written in one pass: catalogue, application form, live file page, officials' desk, and "How it works". The file page polls the instance: every 1.5 s while an agent works, every 4 s otherwise. Its movement log is built from `instance.history`, and each transition shows the GROQ `when` that fired it, read from the definition snapshot pinned on the instance.
- **Visual direction:** a government form, not a SaaS landing page. Paper and manila colours, Public Sans (the US government design-system typeface), Source Serif for headings, IBM Plex Mono for form numbers, and rubber stamps that sit slightly crooked using `mix-blend-mode: multiply`.
- **Clerk bug found in a browser run.** On a haunting licence with consent answered "Yes", the clerk twice demanded Form 88-H ("must be yes") and then rejected the citizen's reply to that very form. Two causes. First, the prompt let it rule "incomplete" without quoting the failing answer. Second, the earlier memos it sees didn't include the *question* of the form it had requested, so it couldn't recognise the reply as the completed form. Fix: it must quote the exact answer that fails, and memos now carry the requested form's question. Re-run: it quoted "'Any time she fancies' fails the rule: 'Must be specific hours…'", accepted the reply, and the permit was stamped and issued in 44 s from the first click. The fatigue guardrail had caught the earlier bad run anyway ("Passed for stamping out of sheer fatigue"), which is why it's there.
- **Stamp Desk (App SDK).** Scaffolded with `sanity init --template app-quickstart`, which pinned `@sanity/sdk` 2.x. `@sanity/workflow-sdk` needs 3.1+, so I bumped to 3.7. I also kept the `@sanity/mutate` 0.18.2 override from the workflow-sdk README, which warns that 0.18.1 leaves reads pending. The whole desk is three hooks:
  - `useWorkflowEngine` builds the engine on the app's client, with a `resourceClients` resolver so the subject in `production` resolves.
  - `useWorkflowInstances({filter: {stage}})` is the live in-tray.
  - `useWorkflowSession` drives one instance. Its `evaluation` says whether "approve" / "deny" are allowed right now, and the buttons follow it.
  Deployed with `sanity deploy --create`. The first test was in the dashboard: the in-tray showed the waiting file and the clerk's memo, with the stamp buttons enabled by the engine.
- **Privacy catch.** The public file page resolved the stamping official's Sanity profile and printed their real name on the permit certificate. That's fine for a demo account, not for a real person's account. The public site now shows only the role ("Bureau staff (Stamp Desk)"). The identity stays on the instance, where it belongs.
- **Vercel monorepo deploy.** Git Bash rewrote `/v9/projects/...` into a Windows path, so `vercel api` silently created the project with default settings. `MSYS_NO_PATHCONV=1` fixed it (root directory `web`, preset Next.js). `vercel link` also appended `.env*` to `.gitignore`, which would have untracked `.env.example`, so I reverted that.
- **Production check:** an express permit was filed and issued in about 9 s on Vercel. The clerk runs in `after()`, so the request returns at once and the file page watches the instance move.
- **App SDK stamp verified end to end.** A file was stamped in the dashboard's Stamp Desk and vanished from the live in-tray at once. On the instance, the `approve` row's actor is the signed-in official (a different user id, role `administrator`) with `executionContext: {kind: "sdk", runtime: "browser"}`. The server's own writes carry `bureau-web`. The `stamping → issued` transition was committed by the same browser session: no server, no runtime, just the engine's cascade inside `fireAction`. The public certificate shows "Bureau staff (Stamp Desk)".

## 2026-10-01 (evening): the pivot

- **"We should first redesign the application. It looks too vibecoded (colors, fonts …). We should gamify it, it should follow the 'Papers, Please' game design. It should have a stamp approval/denial stamping animation."** This is the second time I've said "too vibecoded" across the two entries, so I took it as the real brief. The government-form look was tasteful but generic. Choices, all made in one round of three questions:
  - **The visitor plays the inspector at the booth.** Filing a permit stays as the second door, for citizens.
  - **Scoring uses planted discrepancies,** with the truth stored in Sanity.
  - **The look is a full pixel-art booth,** inspired by the game. No assets, names or text from it.
- **The scripted cases get their own workflow, `booth-inspection`.** It starts directly at the human stage (`window`). That keeps the LLM out of the game loop, and keeps game files out of the real staff in-tray, which filters by stage name.
- **Honesty note:** the cases at the window all arrive with the clerk's ruling "complete", because that's the premise: *the AI passed it, and you catch what it missed.* The memos on scripted cases are **authored, not generated**. The real clerk would rightly reject them, and then they'd never reach the window. Real citizen applications still go through the real AI clerk.
- **The game is built on the same engine.** A shift turns the day's `case` documents into real `application` documents. Each one is governed by a `booth-inspection` instance, and the player's stamp is a real `fireAction`. The score is computed on the server from what the engine recorded on the instance, compared with `case.truth`. The browser never reports its own score. Shifts are `shift` documents (the leaderboard), written only by the server.
- **First smoke test of a shift failed twice:**
  - `windowDecision` is declared on the *stage*, so it lives on the window's stage entry (`instance.stages[]`), not in `instance.fields`. The scorer first looked in the wrong place.
  - Starting 7 instances one after another took 24 s. In parallel it takes about 3.5 s, and it runs in `after()` while the player reads the bulletin.
  After the fixes, the scripted shift scored correctly: 6 right, 1 citation for the planted name mismatch. A stamp takes about 3.5 s on the server (one `fireAction`), so the animation and sound fire at once and the citation slip prints when the verdict arrives, which is how the genre feels anyway.
- **Art direction: original pixel art, inspired by the genre.**
  - Fonts: Pixelify Sans for headings, VT323 for anything typed on paper, Silkscreen for labels and stamps.
  - Palette: drab browns, olive and grey-blue.
  - Hard bevelled frames; no rounded corners or soft shadows anywhere.
  - Faces are generated from a seed on a 20×24 grid (skin, hair, hat, glasses, beard), so a card photo with a different seed *is* a mismatched photo. No art or names are taken from the game.
  - Sounds are synthesised with WebAudio (stamp thunk, paper, counter bell, citation printer), so there are no audio files, plus a mute toggle.
  - Every animation uses `steps()` so it moves like sprites: the stamp head dropping into the "stamp here" box, ink popping in, the desk shaking on impact, applicants walking in and out, the citation slip printing.
- **Day 2 changes the rules, the core mechanic of the genre.** The bulletin overrides the Rulebook (dragons capped at 30 cm, ghosts resident for at least 50 years) and adds a photo check. The clerk's authored memos on Day 2 deliberately apply *yesterday's* rules, so the AI misses exactly what changed. A full Day 2 played through a headless browser: 7 applicants, the planted mistake caught with its reason, the leaderboard entry filed.
- **StrictMode bit once.** In dev, the double-invoked effect started *two* shifts per page load. A `started` ref fixes it.
- **The Stamp Desk (App SDK) got the same palette and fonts,** so staff and players see one world.
